# connect.html 四分頁合併為單頁 — 設計文件

- 日期：2026-07-26
- 專案：`isms-connect-asset`
- 影響檔案：`connect.html`（主要）、`code.js`（移除失效端點）

## 1. 背景與問題

`connect.html` 目前有四個分頁：資訊資產清單（實際內容是**資產**）、對照作業、資訊資產、報表查詢。

核心痛點是**對照流程被分頁切斷**：使用者在「資訊資產清單」勾選資產後，必須點「前往對照」跳到另一個分頁才能選擇資訊資產並建立對照。流程不連續。

調查後發現三個既有事實，決定了本設計的方向：

1. **四個分頁的資料在 `DOMContentLoaded` 時已全部載入完畢**，分頁只是視覺上的隱藏。合併不會增加後端負擔。
2. **主表每一筆資產已帶著 `group`、`isMapped`、`mappedIsmsAssetId` 回到前端**（`getAssetsWithMappingStatus` 的回傳）。後三個分頁的功能（依資訊資產查詢、組別統計、匯出）所需原料前端全部現成，可純前端計算。
3. **首載 5 支後端呼叫中，`getGroupList()` 與 `getMappingStatistics()` 內部各自又完整呼叫一次 `getAssetsWithMappingStatus()`** — 財產總表與物品總表在一次開頁中被完整讀了三遍。

因此本設計不是「把四頁塞進一頁」，而是**把後三個分頁重新理解為同一份資料的不同切面**，轉化為主清單上的篩選器與操作。

## 2. 目標與非目標

**目標**
- 勾選資產到建立對照，視線不離開資產清單，不需切換分頁。
- 「依資訊資產查詢」「組別統計」「匯出」轉化為主清單的篩選與操作。
- 首載後端呼叫 5 → 3；兩張總表完整重讀 3 次 → 1 次。

**非目標（明確不做，避免範圍蔓延）**
- 不修改任何後端業務邏輯（僅移除已失效的端點）。
- 不動權限模型（`assertWriteAccess_` 守門維持現狀）。
- 不動 `index.html` 與 `softwarelist.html`。
- 不改資產表的欄位組成，保留既有欄寬修正（`.cell-name` / `.cell-brand` / `#assetTable { width: auto }`）。
- 不引入前端框架，維持 vanilla JS。

### 元件職責

| 元件 | 職責 | 取代 |
|------|------|------|
| 統計卡 | 顯示當前篩選下的四個數字。「已對照」「未對照」兩張可點擊套用對照狀態篩選（再點取消）；「總數」點擊＝清除對照狀態篩選；「對照率」純顯示不可點 | 原 `☐僅顯示未對照` checkbox |
| 組別晶片列 | 每顆顯示組別名＋筆數，點擊篩選，再點取消 | 原「全部組別」下拉 ＋ 報表查詢的組別統計表 |
| 資訊資產下拉 | 選定後篩出 `mappedIsmsAssetId === 選定值` 的資產 | 原「資訊資產」分頁 ＋「依資訊資產查詢」 |
| 底部動作條 | 已選清單、選資訊資產、備註、建立對照 | 原「對照作業」分頁 |

### 計數規則：每個分面排除它自己那一維

分面搜尋（faceted search）的標準做法——**每個分面的計數都排除自己的維度**，只對其他維度反應：

- **統計卡**（總數／已對照／未對照）：套用**除 `mappedStatus` 以外**的所有條件。
- **組別晶片**：套用**除 `group` 以外**的所有條件。

理由相同：若分面也套用自己的條件，點下去之後其他選項會全部歸零，就再也不能比較、也不能點回去。實例——點「已對照」時，若統計卡套用了狀態條件，「未對照」會變 0、「總數」會變 3，三張卡同時失效。

行為對照（791 筆、3 筆已對照、兩組）：

| 操作 | 統計卡 | 組別晶片 | 表格列數 |
|------|--------|---------|---------|
| 初始 | 791 / 3 / 788 | 402、389 | 791 |
| 點「已對照」 | **不變** | 2、1 | 3 |
| 點「資訊組」 | 402 / 2 / 400 | **不變** | 402 |

副作用（刻意接受）：狀態篩選啟用時「資產總數」不等於表格列數。選中卡片的藍色外框即是用來標示目前正在看哪個子集。

### 底部動作條行為

- 顯示條件：`selectedAssetIds.size > 0`；為 0 時完全隱藏，不佔版面。
- 點「已選 N 筆」展開已選清單浮層，可逐筆移除（沿用既有 `removeFromSelection`）。
- 資訊資產選擇沿用既有的搜尋框 + `<select>`，僅版面由兩欄面板壓縮為一條。

## 4. 資料流

```
allAssets ──┬─→ 組別清單（去重排序）───────────→ 晶片列渲染
            ├─→ filtered = 套用全部篩選 ───────→ 表格 + 統計卡 + 匯出範圍
            └─→ 各組計數 = 套用「除組別外」篩選後 groupBy → 晶片數字
selectedAssetIds ─→ 底部動作條顯示/隱藏 + 已選清單
```

單向推導。任何篩選變動只觸發一次重算與重繪，不打後端。

**首載（3 支，平行）**

| 呼叫 | 用途 |
|------|------|
| `getCurrentUser()` | 顯示登入者 |
| `getAssetsWithMappingStatus({})` | → `allAssets`，**唯一資料真相** |
| `getIsmsAssets({})` | → `allIsmsAssets`，前端過濾 HW/EV |

**建立對照後**：`createMappings` 成功 → `loadAssets()` 重載 → 統計卡與晶片自動重算。原本額外的 `loadStatistics()` 呼叫移除。

**匯出**：前端從 `filtered` 組 CSV，以 `allIsmsAssets` 建 Map 補資訊資產名稱與類別。欄位與檔名沿用原後端 `exportMappingReport` 格式（10 欄、`資產對照報表_YYYY-MM-DD.csv`），確保既有使用者拿到的檔案格式不變。

## 5. 後端清理

以下端點在本次重構後無任何前端呼叫，且經全檔搜尋確認無其他後端函式內部呼叫，一併從 `code.js` 移除：

| 端點 | 移除理由 |
|------|---------|
| `getGroupList` | 組別清單改前端從 `allAssets` 去重取得 |
| `getMappingStatistics` | 統計改前端計算（且只有前端算得出「當前篩選下」的數字） |
| `getAssetsByIsmsAsset` | 改為前端篩選 `mappedIsmsAssetId` |
| `exportMappingReport` | 改為前端組 CSV |
| `updateMapping` | **本次重構前即為死碼**。功能被 `createMappings` 完全涵蓋（後者對既有對照會直接更新） |

**明確保留** `deleteMappings`：它同樣是死碼（無任何 UI 呼叫），但它是程式中**唯一能移除對照記錄的路徑**。使用者已就此單點決定保留，作為必要時可從編輯器手動執行的維運工具。它維持既有的管理員守門（`assertWriteAccess_(true)`），本次不做任何更動。

`code.js` 中為這些端點加的權限守門（`assertWriteAccess_`）隨函式一併移除；刪除端點比守門端點更能減少攻擊面。

## 6. 錯誤處理

順帶修補三個既有缺口（皆位於本次要改的程式路徑上）：

1. `loadUserInfo()` 目前**沒有** `withFailureHandler`，失敗時使用者資訊欄永遠空白且無提示 → 補上。
2. 現有失敗處理只有 toast，表格的 loading spinner 會**永遠轉下去**（違反 PLAYBOOK §4-9）→ 改為 spinner 收斂成錯誤列，附「重試」按鈕。
3. `allIsmsAssets` 載入失敗時，資訊資產下拉與底部動作條的選單停用並顯示原因，但**不阻擋主清單** — 資產清單仍可瀏覽、篩選、匯出。

**空狀態**：篩選後 0 筆時，表格顯示空訊息、統計卡歸零、晶片全部顯示 0 但**仍然渲染**（若整列消失，使用者將無法點回其他組別）。

## 7. 驗收清單（手動，無自動化測試）

1. 未套用任何篩選時，晶片數字加總 = 統計卡「總數」。
2. 勾選「未對照」後，各組晶片數字下降但**不歸零**，加總 = 統計卡「未對照」數。
3. 點「資訊組」晶片後，其他組晶片數字**維持可見且不變**（驗證晶片排除組別自身維度）。
4. 資訊資產下拉選 IT-EV-001，篩選結果與舊版「依資訊資產查詢」的結果逐筆一致。
5. 匯出檔案與舊版 `exportMappingReport` 產出的 CSV 逐欄比對，欄位順序與標題一致；筆數 = 當前篩選結果筆數。
6. 勾選 2 筆 → 底部動作條滑出；取消勾選至 0 筆 → 完全隱藏且不佔版面。
7. 對已有對照的資產建立新對照，覆蓋確認彈窗仍正常跳出。
8. 條碼掃描仍可用，7-4-7 格式化與 2 秒冷卻機制不變。
9. 資產表欄寬正常：資產名稱欄 180px、廠牌型號 ≤240px 且長內容折行不截斷。
10. 用非管理員白名單帳號操作，建立對照仍可成功（權限模型未被更動）。

| 風險 | 緩解 |
|------|------|
| 組別數量過多導致晶片列過長 | 晶片列水平捲動；若實測超過約 12 組，改為前 N 組 + 「更多」下拉。實作時以實際組別數決定 |

| 移除的 5 支端點日後若被發現仍有用途 | 皆可從 git 歷史復原；本次已全檔搜尋確認無前端與後端呼叫者 |
